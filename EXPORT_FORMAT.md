# Export format

_Generated by `clm-lib export`; do not edit (it is rewritten on every export)._

## Who owns what

| Files | Owner | Export behaviour |
| --- | --- | --- |
| `README.md` (root), `experiments/<id>/README.md`, `SUMMARY.md`, `protocol.md` | this repository (hand-written) | never overwritten; a starter is created only if missing |
| `experiments/<id>/manifest.json`, `report.md`, `metrics.json`, `metrics.csv` | exporter (generated) | regenerated on every export |
| `experiments/<id>/artifacts/**` | exporter (immutable evidence) | written once; a differing copy is refused |
| `experiments/<id>/SHA256SUMS`, `EXPORT_FORMAT.md` | exporter (generated) | rewritten on every export |
| `ledger-snapshots/` | exporter (historical copies) | content-addressed; never overwritten |

Experiment selection (`experiment.json`: run ids, roles, settings, provenance) lives in clm-lib.
Write-ups, findings and historical protocols live here.

## Checksums

- **Immutable trees:** every run, fixture, comparison and source tree under `artifacts/` has its
  own `SHA256SUMS`. Re-exporting identical evidence is a no-op; different evidence under an
  existing name stops the export.
- **Experiment level:** `experiments/<id>/SHA256SUMS` covers `artifacts/**` and the generated
  files. It **excludes** the hand-written `README.md`, `SUMMARY.md` and `protocol.md`, so editing
  a write-up never looks like corrupted evidence. Before it is rewritten, its existing
  `artifacts/` entries are re-verified.
- **Verify:** run `sha256sum -c SHA256SUMS` inside a folder. Header lines starting with `#` are
  comments.

## Layout of an experiment folder

- `artifacts/runs/<role>/<run_id>/`: one run's evidence. Roles are:
  - `evaluation`: comparison runs;
  - `guided`: prompted demonstrations;
  - `calibration`: development runs;
  - `smoke` and `access-failure`: connectivity checks.

  Inside a run folder:
  - `run.json`: configuration;
  - `events.jsonl`: event log;
  - `requests/`: exact model requests (no headers);
  - `context/`: accepted context revisions and diffs;
  - `scripts/`: model-written code, saved before it ran;
  - `files/`: workspace files before and after each step;
  - `workspace/`: the final sandbox workspace;
  - `evaluator/`: truth and score, written after the run;
  - `summary.json`: metrics.
- `artifacts/fixtures/<task>/`: the task files, verified against each run's copy.
- `artifacts/comparisons/<stamp>/`: comparison records, frozen settings and source patches.
- `artifacts/source/`: provenance patches.

Run files are copied unchanged, except for the redactions listed in each `manifest.json`.
